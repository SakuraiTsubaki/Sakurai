# ROM layout: 0x000000-0x0003A3

Status: **confirmed across all seven uploaded LeafGreen ROMs**

This is the first reconstructed layout segment. The ROMs were treated as read-only inputs.

## Segment map

| ROM offset | Size | Interpretation | Cross-version status |
|---:|---:|---|---|
| `0x000000` | `0x4` | ARM branch to `start_vector` | identical (`EA00007F`) |
| `0x000004` | `0x9C` | Nintendo logo data | identical |
| `0x0000A0` | `0x20` | standard GBA cartridge header fields | title shared; game code / revision / checksum vary |
| `0x0000C0` | `0x40` | reserved/GPIO/header padding region | identical |
| `0x000100` | `0x104` | Game Freak compatibility header (`GFRomHeader`) | structure shared; language and pointers vary |
| `0x000204` | `0x44` | `start_vector` + literal pool | code shared |
| `0x000248` | `0x154` | `intr_main` | instruction bytes shared |
| `0x00039C` | `0x8` | `intr_main` literal pool | WRAM addresses vary by build |
| `0x0003A4` | — | `AgbMain` Thumb entry | next segment |

## Entry point

The first word in every ROM is:

```text
EA00007F
```

Decoded as an ARM immediate branch at ROM offset `0x000000`, it targets ROM offset `0x000204` (`0x08000204` in the GBA Game Pak address space).

This means the executable entry skips over both the standard GBA cartridge header and the Game Freak compatibility header.

## Standard GBA header

All seven ROMs use the title `POKEMON LEAF` and maker code `01`.

| Target | Game code | Software version | Header checksum |
|---|---|---:|---:|
| Japan | `BPGJ` | 0 | `0x7C` |
| USA | `BPGE` | 0 | `0x81` |
| Europe Rev 1 | `BPGE` | 1 | `0x80` |
| Germany | `BPGD` | 0 | `0x82` |
| France | `BPGF` | 0 | `0x80` |
| Italy | `BPGI` | 0 | `0x7D` |
| Spain | `BPGS` | 0 | `0x73` |

The standard GBA complement checksum recalculates correctly for all seven images.

## Game Freak compatibility header at 0x100

The structure occupies exactly `0x104` bytes, from `0x000100` through `0x000203`. This placement explains why the cartridge entry branch lands exactly at `0x000204`.

All targets contain:

- version = `5` (LeafGreen)
- game name = `pokemon green version`

Language values observed directly in the ROMs:

| Value | Language | Targets |
|---:|---|---|
| 1 | Japanese | Japan |
| 2 | English | USA, Europe Rev 1 |
| 3 | French | France |
| 4 | Italian | Italy |
| 5 | German | Germany |
| 7 | Spanish | Spain |

The header also contains direct ROM pointers to Pokémon front/back sprite tables, normal/shiny palettes, icons, species names, move names, decorations, and additional save/data structures. Exact per-target pointers are recorded in `header_matrix.csv`.

## Startup code

Confirmed symbols:

```text
0x08000204  start_vector   ARM
0x08000248  intr_main      ARM
0x080003A4  AgbMain        Thumb
```

At `0x000244`, every target contains the literal `0x080003A5`; bit 0 marks a Thumb target, resolving to `AgbMain` at `0x080003A4`.

The startup/intr handler instruction bytes from `0x000204` through `0x00039B` are identical in all seven ROMs. The first cross-version differences after executable entry occur in the two literal words at `0x00039C` and `0x0003A0`, which point into build-specific IWRAM layouts.

## External structural cross-check

The observed layout was cross-checked against the public `pret/pokefirered` reconstruction:

- `src/rom_header_gf.c`

These references are used as a structural cross-check only; the addresses and target matrix above were measured from the uploaded LeafGreen ROMs.

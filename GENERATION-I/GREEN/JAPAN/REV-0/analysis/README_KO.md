# GREEN1025 — Pocket Monsters Midori 전국도감 1~1025 확장 기반

## 이번 빌드에서 실제 적용된 것
- 원본 ROM은 읽기 전용으로 유지한다.
- Rev.0 / Rev.A 각각 SHA-1을 엄격 검증한다.
- 512 KiB MBC1 ROM을 **4 MiB MBC5+RAM+BATTERY** 컨테이너로 확장한다.
- 외부 SRAM 헤더를 32 KiB → **128 KiB**로 확장한다.
- 기존 0x00000~0x7FFFF 데이터는 카트리지 헤더/체크섬 필드를 제외하고 보존한다.
- 새 Bank $20(파일 오프셋 0x80000)에 `G1025DB` 디렉터리를 설치하고 1025종 데이터 영역을 예약한다.
- 헤더 체크섬과 글로벌 체크섬을 다시 계산한다.
- Rev.A 원본의 151종 BaseStats(28바이트 × 151)를 별도 추출해 회귀 검증 자료로 만든다.

## 1025종 파라미터 ABI
종 번호는 8비트가 아니라 `uint16`으로 정의한다. 현대 6종족값은 원장에 모두 보존하고, 1세대 실행용 Special은 `(Sp.Atk + Sp.Def)/2` 반올림값으로 만든다. 현대 타입 18종은 원본 번호를 최대한 보존하면서 Steel=$09, Dark=$1B, Fairy=$1C를 추가한다. 원본의 타입 기반 물리/특수 분류를 유지하므로 Steel은 물리, Dark/Fairy는 특수로 취급한다.

현대의 특성·성별·알그룹·기본 친밀도·EV 지급·신장·체중·전설/환상 플래그는 **손실 없이 메타데이터에 보존**하되, 원본 녹에 없는 시스템은 자동으로 전투 효과를 만들지 않는다. 기초 경험치가 255보다 큰 종은 원본 1바이트 실행 필드에서는 255로 제한하고 원본 값은 16비트 메타데이터에 보존한다.

## 아직 “플레이 가능”으로 연결되지 않은 부분
Stage-0은 저장공간/매퍼/데이터 계약을 실제 ROM에 설치한 기반 빌드다. 1025종을 전투·파티·박스에서 실제 선택하려면 다음 엔진 경로가 모두 16비트 종 ID를 읽도록 바뀌어야 한다: `LoadMonData`, `wCurSpecies/wPokedexNum`, 파티/박스 구조, 트레이너/야생 테이블, Seen/Caught 비트셋, 진화·기술표, 이름/도감 UI, 스프라이트·울음소리 포인터, 저장/체크섬. 따라서 현재 Stage-0 ROM을 “1025종 완전 플레이 가능판”이라고 부르지 않는다.

## 데이터 빌더
`tools/build_species_db.py`는 `steffanossa/pokemon_dataset`의 1025행 CSV 스키마를 입력받아 64바이트 × 1025종의 정적 파라미터 DB를 만든다. 데이터 출처는 최종 통합 전에 PokéAPI/공식 자료로 교차검증하는 것을 전제로 한다. 기술폭과 복잡한 진화조건은 별도 테이블로 확장하며 임의로 누락하거나 가짜 값을 넣지 않는다.

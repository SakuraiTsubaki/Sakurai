# GS Korean → ポケットモンスター 신규 한국어화: 초기 전수조사

## 조사 원칙

- 이번 결과는 이전 분석물을 전제로 삼지 않고, 현재 제공된 ROM에서 처음부터 다시 계산했다.
- 원본 ROM은 읽기 전용 입력으로만 사용했다.
- 결과물에는 ROM 데이터나 추출 그래픽·문자열 원문을 포함하지 않는다.
- 파일명은 분류 보조값이며, 실제 판본 식별의 기준은 SHA-1과 SHA-256이다.

## GS Korean 기준 ROM

`Pocket Monsters Geum (Korea)`는 2,097,152바이트, 128뱅크 ROM으로 확인됐다.

- SHA-1: `c0ff3999e1093e1af59ef3eea3f1bfd7c1f18a65`
- SHA-256: `9c273e86e6120c6a038160ccb0153b8b20425b84fc08a496281c1d1bcac492f6`
- 헤더 표기 ROM 크기와 실제 파일 크기 일치
- Nintendo 로고, 헤더 체크섬, 글로벌 체크섬 모두 정상

## 초기 구조 비교에서 확인된 사실

한국판 금은 일본판 금보다 ROM 용량이 1 MiB에서 2 MiB로 확장되어 있다. 그러나 전부 새로 배열된 ROM은 아니다. 한국판 금에서 내용이 있는 뱅크 가운데 20개가 일본판 금의 동일 번호 뱅크와 바이트 단위로 완전히 일치한다.

동일한 비공백 뱅크 번호는 다음과 같다.

`0C, 12, 15–20, 2A, 30, 37, 3B–3D`

영어판 금과도 비공백 뱅크 7개가 동일 번호에서 완전히 일치한다.

`0C, 2A, 30, 37, 3B–3D`

이는 한국판이 원본 엔진의 일부 뱅크를 그대로 유지하면서 한국어 표시·텍스트·그래픽에 필요한 영역을 선택적으로 변경하거나 확장한 구조라는 강한 증거다. 단, 각 변경 뱅크의 기능은 아직 확정하지 않았으며 후속 코드·포인터 추적으로 검증한다.

## 후속 정밀조사 후보

한국판 금의 다음 뱅크는 실제 데이터가 있으며, 일본판·영어판과의 구조 차이 및 한글 관련 데이터 여부를 우선 검증할 후보로 분리했다.

| 뱅크 | 엔트로피(bit/byte) | 00 바이트 | 서로 다른 바이트값 | 현재 판정 |
| --- | ---: | ---: | ---: | --- |
| `68` | 4.773473 | 5,625 | 243 | 데이터 있음, 기능 미확정 |
| `69` | 4.652782 | 6,068 | 238 | 데이터 있음, 기능 미확정 |
| `6A` | 0.000000 | 16,384 | 1 | 전부 00, 사용 안전성 미확정 |
| `6B` | 0.000000 | 16,384 | 1 | 전부 00, 사용 안전성 미확정 |
| `6C` | 3.691596 | 8,479 | 224 | 데이터 있음, 기능 미확정 |
| `78` | 3.410483 | 8,758 | 90 | 데이터 있음, 기능 미확정 |
| `79` | 3.921904 | 6,781 | 77 | 데이터 있음, 기능 미확정 |
| `7A` | 3.473205 | 8,705 | 98 | 데이터 있음, 기능 미확정 |

`6A`와 `6B`가 물리적으로 00으로 채워졌다는 사실만으로 자유 공간이라고 확정하지 않는다. 뱅크 전환 코드, 포인터, 체크 루틴에서 참조되지 않는지 확인한 뒤에만 사용 가능 영역으로 판정한다.

## 판본 차이 기준선

| 비교 | 다른 바이트 | 차이 구간 | 변경 뱅크 |
| --- | ---: | ---: | ---: |
| 영어 Crystal Rev 0 ↔ Rev A | 584 | 79 | 8 |
| 일본 Gold Rev 0 ↔ Rev A | 10,841 | 426 | 10 |
| 일본 Pikachu Rev B ↔ Rev 0A | 307,668 | 8,113 | 61 |
| 일본 Pikachu Rev B ↔ Rev D | 247,838 | 22,172 | 61 |
| 일본 Pikachu Rev 0A ↔ Rev D | 320,147 | 16,944 | 61 |
| 일본 Red Rev A ↔ Rev 0 | 46,167 | 5,437 | 31 |

판본명이 비슷하더라도 차이가 헤더 몇 바이트에 국한되지 않는다. 따라서 어느 한 판본에서 찾은 주소를 다른 판본에 그대로 적용하지 않고, 판본별 포인터와 호출 지점을 독립적으로 기록한다.

## 다음 단계

1. 한국판 금의 128개 뱅크를 일본판 금 Rev 0·Rev A 및 영어판 금과 기능 단위로 대응시킨다.
2. 2bpp 타일 반복성, 문자 인덱스 테이블, 2바이트 코드 패턴을 이용해 한글 폰트 후보를 ROM 자체에서 다시 찾는다.
3. 후보를 참조하는 코드와 뱅크 전환 루틴을 역추적해 폰트·인코딩·출력 루틴을 각각 확정한다.
4. 확정된 문자표로 왕복 변환 시험을 수행하되, 원본과 동일한 입력을 재조립했을 때 ROM 전체 SHA가 일치해야 통과로 처리한다.
5. 이후에만 일본어판·영어판 대상 ROM별 이식 설계를 시작한다.

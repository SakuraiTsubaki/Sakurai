# Crystal 7-ROM bank-by-bank census + disassembly protocol

## Rule

A bank is **not complete** merely because its bytes, hashes, entropy, or cross-version differences have been catalogued. From now on, each bank is handled as one work unit and only advances to `complete` after both census and disassembly criteria are met.

## Per-bank work unit

1. **Physical census** — verify bank offset, size, SHA-1/CRC32, zero/FF padding, and cross-ROM byte differences.
2. **Semantic census** — identify code, data, text, graphics, scripts, tables, padding/unused regions, and upstream semantic anchors where available.
3. **Control-flow disassembly** — recursively decode reachable LR35902 code from trusted entry points; record calls/jumps, intra-bank labels, external/banked targets, and still-unclassified ranges.
4. **Semantic lifting** — replace provisional numeric labels with stable semantic symbols by aligning the exact EN0/EN1, JP0, ES0, and FR0 source trees; infer and then verify DE0/IT0 counterparts.
5. **Data decoding** — decode non-code regions according to their actual format instead of forcing them through an instruction decoder.
6. **Cross-version mapping** — record moved routines, inserted/deleted data, pointer changes, localization-only routines, revision-only changes, and EU-only bank usage.
7. **Reassembly verification** — every semantic replacement must preserve the exact bytes of the target bank; eventual whole-ROM output must reproduce the original SHA-1.

## Confidence states

- `confirmed`: backed by exact source, exact binary structure, or byte-exact reconstruction.
- `provisional`: derived from recursive control flow or cross-version signatures but not yet semantically anchored.
- `unclassified`: bytes whose format/role is not yet proven.

## Completion gate

A bank may be marked `complete` only when:

- all 0x4000 bytes are accounted for as code/data/unused;
- every executable region is disassembled or intentionally included as a verified binary asset with a documented format;
- every region-specific/revision-specific difference has an explanation or an explicit unresolved marker;
- generated bytes match the original 16 KiB bank exactly;
- the bank can participate in an eventual whole-ROM exact rebuild.

## Current starting point

Bank `00` is the first integrated work unit. Its vectors and header are confirmed; the resident Home engine has a provisional recursive control-flow disassembly for all seven ROMs. Semantic lifting and non-code data boundary confirmation remain in progress.

# Repository Structure

Sakurai starts intentionally small. Directories are added only when real aggregate material exists.

Expected long-term areas may include `registry/`, `research/`, `specs/`, `comparisons/`, `verification/`, `tools/`, `manifests/`, and `docs/`.

The structure is responsibility-based, not generation-tree or structure-version based.

Rules:

- no live `vN` architecture roots;
- no `MIGRATED`, `PRE-Vx`, legacy-history, or retired-tree mirrors;
- no moving canonical game/project work into Sakurai merely to aggregate it;
- use stable IDs, indexes, manifests, and references to connect repositories;
- Git history is the sole history layer.

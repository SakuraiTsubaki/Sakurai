# Repository Structure v11

Status: **canonical** — 2026-09-13.

v11 keeps the release-coordinate grammar introduced by v10, but changes the repository invariant so that **Tsubaki is the complete non-ROM archive/production superset**. Sakurai remains the curated knowledge/control plane.

## 1. Canonical roots

```text
GEN-XX/
CROSS-GEN/
INFRA/
```

Legacy `LIBRARY/`, `projects/`, `workspaces/`, and pre-v10 ownership paths are migration-only. New work goes under the canonical roots above.

## 2. Release coordinate

```text
GEN-XX/<GAME-ID>/RELEASES/<PLATFORM-ID>/<PACKAGE-KIND>/<RELEASE-ID>/
└── DUMPS/<DUMP-ID>/
```

`RELEASE-ID` identifies an official build/release identity. `DUMP-ID` identifies an exact observed image and is `DUMP-SHA256-<first-16-uppercase-hex>`. Full hashes live in `OBSERVATION.json`.

## 3. Dump subtree

```text
DUMPS/<DUMP-ID>/
├── OBSERVATION.json
├── CATALOGS/
├── NATIVE/
├── EXTRACTED/
├── DECODED/
├── NORMALIZED/
├── CONVERTED/
├── IMPLEMENTATION/
├── PATCHES/
├── BUILD/
├── TABLES/
├── REPORTS/
├── VERIFICATION/
└── TOOLS/
```

Directories are created only when they contain real artifacts.

## 4. Repository invariant

### Sakurai
Sakurai is the curated knowledge/control plane. It stores release/dump identity, provenance, hashes, headers, indexes, catalogs, research, reverse engineering, mapping tables, reports, specifications, analysis tools, and verification evidence.

### Tsubaki
Tsubaki is the **complete non-ROM superset**. If an artifact is legally/project-policy eligible for GitHub and is not an original or modified playable ROM image, it belongs in Tsubaki. This includes all Sakurai-class knowledge artifacts **plus** extracted ROM working assets, decoded/normalized/converted assets, implementation data, patches, build inputs/recipes/logs, production tools, and production verification.

Therefore: **Sakurai ⊆ Tsubaki for project-produced non-ROM artifacts at the same semantic coordinate**, except repository-specific metadata.

## 5. ROM exclusion

Never commit original ROM images or modified/playable ROM images (`.gb`, `.gbc`, `.gba`, `.nds`, etc.). Hashes, manifests, tables, scripts, patches, extracted assets, reports, and reproducibility metadata remain tracked.

## 6. Generation V coordinates observed in this cutover

```text
GEN-05/BLACK/RELEASES/NDS-TWL/CART/IRBO-HV0/
GEN-05/WHITE/RELEASES/NDS-TWL/CART/IRAO-HV0/
GEN-05/COMPARES/BW-IRBO-HV0__IRAO-HV0/
```

These release IDs come from the actual NDS headers of the supplied Black/White images; dump IDs are content-addressed from SHA-256.

## 7. Migration rule

Pre-v11 paths are not used as templates. Move/copy verified content into the v11 coordinate first, preserve provenance, then retire the old path. Do not silently reinterpret a region/language/revision from a filename when the ROM header or independent evidence does not establish it.

# Repository Structure v11

Status: **canonical** — 2026-09-13.

v11 replaces the partial v10 ownership model with a strict release-coordinate model and makes **Tsubaki a non-ROM superset repository**.

## Canonical roots

```text
GEN-XX/
CROSS-GEN/
INFRA/
```

## Game coordinate

```text
GEN-XX/<GAME-ID>/
├── RELEASES/
├── PROJECTS/
├── COMPARISONS/
├── REFERENCES/
└── SHARED/
```

## Release coordinate

```text
RELEASES/<PLATFORM-ID>/<PACKAGE-KIND>/<RELEASE-ID>/
```

Exact local observations remain below:

```text
DUMPS/<DUMP-ID>/
```

`RELEASE-ID` identifies a release/build. `DUMP-ID` identifies an exact observed image by SHA-256 prefix. ROM images themselves are never committed.

## Sakurai ownership

Sakurai is the canonical knowledge/evidence repository. Release leaves may contain:

```text
KNOWLEDGE/
├── IDENTITY/
├── DUMPS/<DUMP-ID>/
│   ├── OBSERVATION/
│   ├── LAYOUT/
│   └── VERIFICATION/
├── ANALYSIS/
├── SPEC/
├── REPORTS/
└── TOOLS/
```

## Tsubaki ownership

Tsubaki is the **superset of all project artifacts except ROM images**. It may mirror the Sakurai knowledge package and additionally owns all production material:

```text
KNOWLEDGE/                 # synchronized non-ROM evidence
ASSETS/
├── EXTRACTED/
├── NORMALIZED/
├── CONVERTED/
└── DEDUP/
IMPLEMENTATION/
TOOLS/
PATCHES/
BUILD/                     # no playable ROM images
TESTS/
REPORTS/
MANIFESTS/
CATALOGS/
VERIFICATION/
```

This intentionally means Tsubaki is not an empty consumer queue. If a reproducible non-ROM artifact is produced by the project, it belongs in Tsubaki.

## No ROM-by-chunk loophole

Do not split a ROM into chunks and commit all chunks in a form that trivially reconstructs the ROM. Chunk hashes, indexes, derived metadata, decoded/extracted semantic assets, source code, patches, and verification data are allowed project artifacts.

## v10 migration

`COMPARES/` becomes `COMPARISONS/`. v10 documents remain historical. New work uses v11 immediately. Existing v8/v9/v10 paths are migration inputs only.

# Repository Structure v11

Status: **canonical** — 2026-09-13.

v11 keeps the release-coordinate grammar introduced by v10 and defines the repository invariant as follows: **Tsubaki contains every project-generated artifact except ROM image files themselves.** Sakurai remains the curated knowledge/control subset.

## 1. Canonical roots

```text
GEN-XX/
CROSS-GEN/
INFRA/
```

Legacy `LIBRARY/`, `projects/`, `workspaces/`, and pre-v10 ownership paths are migration-only. New work goes under the canonical roots above.

## 2. Release coordinate

```text
GEN-XX/<GAME-ID>/RELEASES/<PLATFORM-ID>/<PACKAGE-KIND>/<RELEASE-ID>/
└── DUMPS/<DUMP-ID>/
```

`RELEASE-ID` identifies an official build/release identity. `DUMP-ID` identifies an exact observed image and is `DUMP-SHA256-<first-16-uppercase-hex>`. Full hashes live in `OBSERVATION.json`.

## 3. Dump subtree

```text
DUMPS/<DUMP-ID>/
├── OBSERVATION.json
├── CATALOGS/
├── NATIVE/
├── EXTRACTED/
├── DECODED/
├── NORMALIZED/
├── CONVERTED/
├── IMPLEMENTATION/
├── PATCHES/
├── BUILD/
├── TABLES/
├── REPORTS/
├── VERIFICATION/
└── TOOLS/
```

Directories are created only when they contain real artifacts.

## 4. Repository invariant

### Sakurai
Sakurai is the curated knowledge/control plane. It stores release/dump identity, provenance, hashes, headers, indexes, catalogs, research, reverse engineering, mapping tables, reports, specifications, analysis tools, and verification evidence.

### Tsubaki
Tsubaki is the **literal complete non-ROM superset**. The only excluded project files are original, modified, rebuilt, patched, or otherwise playable ROM image files.

Everything else belongs in Tsubaki, including all Sakurai-class knowledge artifacts plus source code, disassembly/decompilation, reconstructed source/data, extracted ROM assets/data, decoded/normalized/converted resources, localization/translation data, implementation data, patches, build inputs/recipes/products/logs, tools, tests, verification, and reproducible intermediate files.

Being extracted, binary, lossless, reconstructive, rebuildable, intermediate, or also stored in Sakurai is not a reason to omit an artifact from Tsubaki.

Therefore: **Sakurai ⊆ Tsubaki for project-produced artifacts at the same semantic coordinate**, except repository-specific metadata and ROM image files.

## 5. Only exclusion: ROM image files

Never commit original, modified, rebuilt, patched, or otherwise playable ROM image files (`.gb`, `.gbc`, `.gba`, `.nds`, `.3ds`, `.cia`, `.xci`, `.nsp`, etc.).

This exclusion does not apply to derived disassembly/decompilation, reconstructed source/data trees, extracted assets, bank analyses, patches, build products, or other non-ROM project artifacts.

## 6. Completion rule

A task is not fully reflected to GitHub until every generated non-ROM artifact has been committed to Tsubaki. Selected summaries or manifests alone are not sufficient when more non-ROM artifacts exist.

## 7. Migration rule

Pre-v11 paths are not used as templates. Move/copy verified content into the v11 coordinate first, preserve provenance, then retire the old path. Do not silently reinterpret a region/language/revision from a filename when the ROM header or independent evidence does not establish it.

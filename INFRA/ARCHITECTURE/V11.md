# Repository Architecture v11

Status: **canonical** — 2026-09-13.

## 1. Goal

v11 makes the repository topology match the project operating rule: **Tsubaki contains every non-ROM artifact.** Sakurai remains useful as the research/control repository, but it is no longer an exclusive destination that can cause analysis artifacts to be missing from Tsubaki.

## 2. Canonical coordinates

```text
GEN-XX/<GAME-ID>/RELEASES/<PLATFORM-ID>/<PACKAGE-KIND>/<RELEASE-ID>/
GEN-XX/<GAME-ID>/PROJECTS/<PROJECT-ID>/
GEN-XX/PROJECTS/<PROJECT-ID>/
GEN-XX/<GAME-ID>/COMPARES/<COMPARE-ID>/
GEN-XX/COMPARES/<COMPARE-ID>/
CROSS-GEN/PROJECTS/<PROJECT-ID>/
CROSS-GEN/COMPARES/<COMPARE-ID>/
```

Top-level canonical roots are `GEN-XX`, `CROSS-GEN`, and `INFRA`. Game directories own `RELEASES`, `PROJECTS`, `COMPARES`, `REFERENCES`, and `SHARED`.

## 3. Release and dump identity

A release is a conceptual official software build. An exact observed image is a dump observation.

```text
RELEASES/<PLATFORM>/<PACKAGE>/<RELEASE-ID>/
├── RELEASE.json
└── DUMPS/<DUMP-ID>/OBSERVATION.json
```

If no stable product/game code exists in the cartridge header, use a deterministic market-language-header-version ID such as `JP-JA-HV1`. `DUMP-ID` is content-addressed from SHA-256.

## 4. Artifact classes

Release/project coordinates can contain artifact-class directories as needed:

```text
ANALYSIS/
TABLES/
REPORTS/
SCHEMAS/
MANIFESTS/
TOOLS/
VERIFICATION/
EXTRACTION/
CATALOGS/
ASSETS/
NORMALIZED/
CONVERTED/
TRANSLATION/
IMPLEMENTATION/
PATCHES/
BUILD/
```

These are artifact classes, not ownership branches. The retired v9-style `SOURCE`, `TARGET`, `COMPARE`, and `REFERENCE` ownership roots must not be recreated for new work.

## 5. Repository inclusion rule

### Tsubaki — complete non-ROM superset

Tsubaki receives all non-ROM project artifacts, including the knowledge/control artifacts that are also stored in Sakurai. A task is not complete if a newly generated non-ROM artifact exists only in Sakurai while Tsubaki is intended to track that project.

### Sakurai — knowledge/control subset

Sakurai receives identity/provenance, analyses, comparisons, reverse-engineering notes, tables, reports, schemas/specifications, research scripts, and verification evidence. Production-only binary assets and build products may remain Tsubaki-only.

### Pair invariant

Generation, game, release, dump, project, compare, and reference IDs are identical between repositories. When the same artifact exists in both, use the same relative canonical path whenever practical.

## 6. ROM binary exclusion

Never commit an original, modified, or playable ROM image (`.gb`, `.gbc`, `.gba`, `.nds`, etc.). Do not evade this by splitting a complete ROM into lossless banks/chunks and committing the pieces. Commit hashes, observations, tables, extraction maps, patches, discrete extracted assets, translated text, implementation data, build recipes, and verification results instead.

## 7. RBY relocalization coordinate

The current Generation I project is canonical at:

```text
GEN-01/PROJECTS/RBY-ENGLISH-RELOCALIZATION/
```

Japanese Red/Green/Blue/Pikachu releases are translation-source inputs. English Red/Blue/Yellow releases are implementation references. Exact dumps are pinned by SHA-256 dump IDs in `PROJECT.json`.

# Repository Path Specification v4.1

Status: canonical for all new work.

## Canonical roots

```text
LIBRARY/
PROJECTS/
INFRA/
.github/
```

Top-level `GAMES/`, `META/`, `GENERATION-*`, and standalone `GEN-*` are legacy migration inputs only. They may remain temporarily while classified, but receive no new work.

## Identity model

Three identities are independent:

1. **RELEASE** — one official software/build identity.
2. **DUMP** — one exact supplied/observed binary image, with hashes and provenance.
3. **PROJECT** — one transformation, localization, modernization, port, integration, rebuild or derived target.

A duplicate dump never creates a second RELEASE. A modified/bad/incomplete dump never creates a fake official RELEASE. A PROJECT never masquerades as an official RELEASE.

## Library path

```text
LIBRARY/GEN-XX/<PLATFORM>/<GAME-ID>/
  RELEASES/<RELEASE-ID>/
    MANIFESTS/
    DUMPS/<DUMP-ID>/
    <RELEASE-OWNED-DOMAIN>/
  COMPARISONS/<COMPARISON-ID>/
  SHARED/
```

For GB/GBC, release IDs use `<MARKET>-<LANGUAGE>-HV<HEADER-VERSION>` unless a stronger platform-native identifier exists. For GBA/NDS/TWL use native game code plus header/software revision when reliable. Later platforms use their strongest native title/build identity.

Recommended DUMP-ID: `<PROVENANCE>-<SHA1-PREFIX>`.

## Project path

```text
PROJECTS/<PROJECT-ID>/
```

Sakurai project sections:

`MANIFESTS`, `CROSSWALK`, `DESIGN`, `IMPLEMENTATION`, `VERIFICATION`, `TOOLS`, `REPORTS`.

A project manifest must lock every source/target to canonical LIBRARY release IDs. Target IDs are project-local but must resolve unambiguously.

## Sakurai ownership

Sakurai is authoritative for release/dump identity, hashes, research, reverse engineering, text/data/map/event structure, disassembly, symbols, unused/dummy/glitch analysis, design specifications, crosswalks and verification evidence.

## Pair contract with Tsubaki

Sakurai and Tsubaki must use the same `RELEASE-ID`, `COMPARISON-ID`, `PROJECT-ID`, and `TARGET-ID`. Artifact responsibility can differ; identity cannot.

## Forbidden new pseudo-owners

Do not create new canonical path components named `MULTI`, `REV-ALL`, `ALL`, `ALL-RELEASES`, `MULTI-REGION`, `GENERAL`, `MISC`, or `OTHER` as release/project owners. Use an explicit comparison ID, project ID, shared scope, or manifest field instead.

## Publication boundary

Original ROM/executable binaries and byte-exact whole-ROM/whole-bank payload archives are not committed. Hashes, manifests, derived structure, reproducible tools, semantic annotations, patches and permissible derived assets may be committed with provenance.

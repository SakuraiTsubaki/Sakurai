# Pokémon Crystal 7-ROM full disassembly strategy

## Objective
Build a reproducible, bank-complete, semantic disassembly for all seven uploaded retail ROMs while preserving byte-perfect provenance and never publishing ROM-equivalent byte dumps.

## Layer A — lossless source skeleton
`emit-lossless-bank-asm.py` turns any 2 MiB Crystal ROM into 128 fixed RGBDS sections (`Bank 00`–`Bank 7F`) using `db` directives. This is intentionally not semantic: its job is to guarantee that every source byte is represented while code/data regions are progressively replaced by labels, instructions, tables, text, graphics includes, and scripts.

Generated byte-complete trees are ROM-equivalent and therefore remain local/read-only working material. Only tooling, hashes, address maps, semantic descriptions, diffs, and original analysis are suitable for repository publication.

## Layer B — semantic anchors already verified
- EN Rev 0 (`f4cd194b...`) exactly matches `pret/pokecrystal` V1.0.
- EN Rev A (`f2f52230...`) exactly matches `pret/pokecrystal` V1.1.
- JP Rev 0 (`95127b90...`) exactly matches `PikalaxALT/pokekuristaru`.
- ES Rev 0 (`889a06fc...`) exactly matches `erosunica/pokecrystal-es`.
- FR Rev 0 (`c055992b...`) exactly matches `qwilvove/pokecrystal-fr`.

DE and IT have no exact semantic source repository confirmed in the current survey; they will be reconstructed by cross-version symbol lifting plus local bank-by-bank disassembly.

## Bank-level method
1. Anchor EN banks to `pret/pokecrystal` `layout.link` section names.
2. Anchor JP/ES/FR to their exact matching semantic repositories and normalize their symbol maps to the EN bank taxonomy.
3. Compare DE/IT against EN/ES/FR using exact byte runs, function signatures, pointer tables, text terminators, graphics compression boundaries, and script opcode structure.
4. Replace Layer-A `db` spans with semantic RGBDS code/data one region at a time.
5. After each replacement, rebuild and verify SHA-1 against the source ROM.
6. Record every moved region, bank expansion, pointer rewrite, and localization-only routine.

## Important relocation finding
In EN0/EN1 and JP0, banks `75`, `76`, `79`, and `7A` are all-zero. In ES/DE/FR/IT, banks `75`, `76`, and `79` contain localization data while `7A` remains all-zero in all seven ROMs. Therefore European versions cannot be modeled as simple same-address text substitutions.

## Deliverables
- 7-ROM bank manifest and pairwise difference matrix.
- Exact EN0↔EN1 diff ranges.
- Per-bank semantic taxonomy (`00`–`7F`).
- Local byte-perfect Layer-A source trees.
- Cross-version symbol/address map.
- Semantic DE/IT reconstruction source.
- Rebuild verification report for every ROM.

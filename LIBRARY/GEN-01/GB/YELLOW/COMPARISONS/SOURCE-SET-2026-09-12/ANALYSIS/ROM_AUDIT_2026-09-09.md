## Bank-level findings

### Japanese revisions

Sequential identical-bank counts:

- Rev 0A → Rev B: 3 identical banks: `19`, `1B`, `32`
- Rev B → Rev C: 4 identical banks: `19`, `1B`, `32`, `33`
- Rev C → Rev D: 3 identical banks: `19`, `1B`, `32`

Sequential byte-difference totals:

- Rev 0A → Rev B: 307,668 changed bytes
- Rev B → Rev C: 39,485 changed bytes
- Rev C → Rev D: 245,538 changed bytes

This is larger than a small patch-only revision pattern and indicates substantial rebuilt/rearranged content in multiple revisions. Semantic classification is still required before assigning causes.

### International language builds

Banks identical across all five unique international language ROMs:

`0C, 1A, 1B, 21, 22, 23, 24, 25, 31, 32, 33, 34, 35, 36, 37, 38, 39`

That is 17 / 64 banks shared exactly across English, French, German, Italian, and Spanish.

Bank `1F` is partially shared: English and Italian are identical there; French, German, and Spanish each differ.

### Japanese Rev D ↔ international lineage signal

Each of the five international language ROMs shares these exact 16 banks with Japanese Rev D:

`0C, 1B, 21, 22, 23, 24, 25, 31, 32, 33, 34, 35, 36, 37, 38, 39`

Earlier Japanese revisions share only two exact banks with English (`1B`, `32`). This strongly supports using Rev D as the primary Japanese structural comparison baseline for the international Yellow builds.

## Recommended next audit stage

Do not treat whole-ROM diffs as semantic changes. Continue bank-by-bank and classify each bank into:

1. executable code / jump tables
2. text and string pointer tables
3. maps / scripts / events
4. Pokémon / move / item / trainer data
5. graphics / tiles / sprites / palettes / SGB or CGB resources
6. sound / music / cry data
7. free space / padding / relocation artifacts

For every bank, record offsets, pointer relationships, cross-version identity, and semantic changes. ROM binaries remain read-only and should not be committed to GitHub.
